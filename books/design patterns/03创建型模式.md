# 📖 第三章：创建型模式——对象的“出生管理局”

大黄翘着二郎腿说：“小灰啊，创建型模式就像对象的‘出生管理局’，专门解决对象怎么‘生’、何时‘生’、生几个的问题！比如直接 new 对象就像硬生孩子，而模式是科学备孕——可控又灵活！”  
小灰挠头：“为啥不直接 new ？简单粗暴多爽！”  
大黄弹了小灰一个脑瓜崩：“笨！如果代码里全是 new，改需求时你得找遍所有 new 的地方，像在垃圾堆里找钥匙！模式让你‘解耦’，像用奶茶店菜单点单，不用关心奶茶妹怎么泡茶！”

🏭 1. 抽象工厂模式（Abstract Factory）——整套“皮肤商城”

小灰：“抽象工厂？是不是开工厂的老板？”  
大黄：“没错！它像‘主题皮肤商城’，比如王者荣耀换皮肤——射手、辅助全套一起换！抽象工厂生产一整套相关对象，保证风格统一。”  
动机：如果代码里写死 new 安卓按钮()，想换苹果风格得改疯。抽象工厂让你一键换整套UI。  
结构：
• 抽象工厂（AbstractFactory）：定义创建产品族的接口，如 createButton()、createDialog()。

• 具体工厂（ConcreteFactory）：实现接口，比如 AppleFactory 生产苹果风按钮和对话框。

• 产品族（Product Family）：一套有关联的产品（比如同一主题的按钮和文本框）。

TypeScript代码示例（用TS因为接口更直观）：
```
// 抽象产品：按钮
interface Button { click(): void; }
// 具体产品：苹果按钮
class AppleButton implements Button {
    click() { console.log("苹果风按钮被点击！"); }
}
// 抽象工厂
interface GUIFactory {
    createButton(): Button;
}
// 具体工厂：苹果工厂
class AppleFactory implements GUIFactory {
    createButton(): Button { return new AppleButton(); }
}
// 客户端代码
function main(factory: GUIFactory) {
    const btn = factory.createButton();
    btn.click(); // 输出：苹果风按钮被点击！
}
main(new AppleFactory()); // 换为AndroidFactory就变安卓风
```
比喻：抽象工厂像“主题套餐”——点‘情侣套餐’得到牛排+红酒，而不是牛排+豆浆！保证产品族不混搭。  
优点：切换产品族容易，符合开闭原则。  
缺点：加新产品得改工厂接口，波及所有子类。

🏗️ 2. 建造者模式（Builder）——乐高式组装大师

小灰：“建造者是不是像搭乐高？”  
大黄：“聪明！它把复杂对象的建造拆成步骤，比如组装电脑：先装CPU，再装内存，最后装显卡。指挥者（Director）控制组装顺序，建造者（Builder）实现具体步骤。”  
动机：如果构造器参数太多（比如10个），直接 new Computer(...) 会疯。建造者让代码像说明书一样清晰。  
结构：
• Builder（建造者）：定义组装步骤，如 buildCPU()、buildMemory()。

• Director（指挥者）：控制组装流程，调用Builder的方法。

• 具体Builder：实现步骤，生产不同配置的产品。

Python代码示例（Python写起来简洁）：
```
class Computer:
    def __init__(self):
        self.parts = []
    def add(self, part):
        self.parts.append(part)
    def show(self):
        print("电脑配置：" + "、".join(self.parts))

# 抽象建造者
class ComputerBuilder:
    def build_cpu(self): pass
    def build_memory(self): pass

# 具体建造者：游戏电脑配置
class GamingComputerBuilder(ComputerBuilder):
    def __init__(self):
        self.computer = Computer()
    def build_cpu(self):
        self.computer.add("i9CPU")
    def build_memory(self):
        self.computer.add("32GB内存")
    def get_result(self):
        return self.computer

# 指挥者
class Director:
    def build(self, builder: ComputerBuilder):
        builder.build_cpu()
        builder.build_memory()

# 客户端使用
builder = GamingComputerBuilder()
director = Director()
director.build(builder)
computer = builder.get_result()
computer.show()  # 输出：电脑配置：i9CPU、32GB内存
```
比喻：建造者像“定制奶茶”——你说“加珍珠、少糖、去冰”，小哥一步步做，不是给你一杯随机混合物！  
优点：分离构造过程，支持不同配置。  
缺点：代码量增加，适合构造复杂对象。

🔨 3. 工厂方法模式（Factory Method）——子类承包的“产线”

小灰：“工厂方法是不是让子类决定生啥对象？”  
大黄：“对！父类定义‘生产线’接口，子类承包具体生产。比如宠物店父类说‘卖宠物’，猫舍子类卖猫，狗舍子类卖狗。”  
动机：避免将具体类硬编码在父类中，提高扩展性。  
结构：
• Product（产品）：抽象接口，如 Animal。

• ConcreteProduct（具体产品）：如 Cat、Dog。

• Creator（创建者）：定义工厂方法 createAnimal()。

• ConcreteCreator（具体创建者）：重写工厂方法，返回具体产品。

C++代码示例（C++的虚函数体现多态）：
```
#include <iostream>
using namespace std;

// 抽象产品
class Animal {
public:
    virtual void speak() = 0;
};
// 具体产品：猫
class Cat : public Animal {
public:
    void speak() override { cout << "喵喵！" << endl; }
};
// 抽象创建者
class PetShop {
public:
    virtual Animal* createAnimal() = 0; // 工厂方法
    void sellPet() {
        Animal* animal = createAnimal();
        animal->speak();
    }
};
// 具体创建者：猫舍
class CatShop : public PetShop {
public:
    Animal* createAnimal() override { return new Cat(); }
};

int main() {
    PetShop* shop = new CatShop();  // 切换为DogShop就卖狗
    shop->sellPet();  // 输出：喵喵！
    return 0;
}
```
比喻：工厂方法像“加盟店模式”——总部规定卖饮料，但北京加盟店卖豆汁，深圳加盟店卖奶茶！  
优点：符合开闭原则，易于扩展。  
缺点：每新增一个产品，就得增加一个创建者子类。

🧬 4. 原型模式（Prototype）——对象的“克隆术”

小灰：“原型模式是复制粘贴吗？”  
大黄：“对！它用‘克隆技术’创建新对象，基于现有原型复制，避免重复初始化。比如游戏里复制怪物，属性一致但内存地址不同。”  
动机：当创建对象成本高（如数据库连接），或需要动态配置时，直接克隆比 new 更高效。  
结构：
• Prototype（原型接口）：定义克隆方法 clone()。

• ConcretePrototype（具体原型）：实现克隆，复制自身状态。

Python代码示例（Python的copy模块方便演示）：
```
import copy

class Monster:
    def __init__(self, name, level):
        self.name = name
        self.level = level
    def clone(self):
        return copy.deepcopy(self)  # 深拷贝
    def display(self):
        print(f"怪物：{self.name}，等级：{self.level}")

# 客户端使用
dragon_prototype = Monster("远古巨龙", 99)
dragon_clone = dragon_prototype.clone()
dragon_clone.display()  # 输出：怪物：远古巨龙，等级：99
```
比喻：原型模式像“复印身份证”——不用重新填表，直接复印一张，但每张都是独立副本！  
优点：避免重复初始化，性能高。  
缺点：深拷贝复杂对象时需小心循环引用。

👑 5. 单例模式（Singleton）——全球唯一“大BOSS”

小灰：“单例就是保证一个类只有一个实例，像公司CEO？”  
大黄：“对！比如数据库连接池、配置管理器，全局只需一份。单例防止重复创建，节约资源。”  
动机：有些对象只需一个实例，多次实例化会浪费资源或导致状态混乱。  
结构：
• 私有构造器：防止外部 new。

• 静态实例：全局唯一。

• 静态获取方法：如 getInstance()。

TypeScript代码示例（懒汉式线程安全版）：
```
class Singleton {
    private static instance: Singleton;
    private constructor() {} // 私有构造器
    public static getInstance(): Singleton {
        if (!Singleton.instance) {
            Singleton.instance = new Singleton();
        }
        return Singleton.instance;
    }
    public showMessage(): void {
        console.log("我是唯一实例！");
    }
}

// 客户端使用
const s1 = Singleton.getInstance();
const s2 = Singleton.getInstance();
console.log(s1 === s2);  // 输出 true，是同一个对象！
s1.showMessage();         // 输出：我是唯一实例！
```
